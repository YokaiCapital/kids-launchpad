## Summary in three lines
- **One route is not dark.** `GET /api/campaigns` is installed, allow-listed and reachable in production with no env var, and it opens or creates a SQLite file at a different path than the import writes to.
- **The fencing token is not enforced by the signer.** Any integer passes; the replay registry, not the token, is what stops a stale runner.
- **Creator media URLs are not validated.** Links are https-only, but picture, banner, video, poster and parent logo URLs accept any scheme and host.

## Medium

### M1. Campaign directory route is live without a flag and opens the wrong registry file
- **Where:** `interaction-review/server/runtime.mjs:67` (`campaignsPlugin()` added unconditionally); `interaction-review/server/campaigns-plugin.mjs:19` (default opener: `openRegistry({driver:'sqlite',path:defaultRegistryPath()})` then `r.migrate()`); `localnet/registry/registry.mjs:433` (`KIDS_REGISTRY_PATH`); `localnet/registry/startup.mjs:12` (`KIDS_REGISTRY_URL`); allow-lists in `interaction-review/deployment/gate.mjs:62-63` and `interaction-review/staging/gateway.mjs:21,35`.
- **Scenario:** After merge and deploy, any site visitor with the site cookie requests `/api/campaigns`. The API process creates `localnet/.runtime/registry.sqlite` (that is `/data/localnet/registry.sqlite` in the Railway image), runs both migrations, and answers an empty directory. The startup import (P3) only runs when `KIDS_REGISTRY_URL` is set and writes to *that* path; the public route reads `KIDS_REGISTRY_PATH` or the default. With `KIDS_REGISTRY_URL=/data/registry/kids.sqlite` the site would show "No open launches" forever while the import fills another file. The comment in runtime.mjs:75 calls P3 "dark"; the read route is not.
- **Impact:** Unflagged production behaviour change, an unauthenticated write path to the volume (file creation and schema), and a silent split-brain between two registry files. No data exposure beyond the empty list.
- **Fix:** Install `campaignsPlugin` only when `KIDS_REGISTRY_URL` is set, and pass it the registry the import opened (`registryImport.registry`) or the same `registryTarget(env)`; delete `KIDS_REGISTRY_PATH`. Make the plugin's lazy opener read-only (no `migrate()`); a missing file is 503, never a fresh empty database.
- **Status: fixed.** `campaignsPluginFor({env, registryImport})` returns null unless `KIDS_REGISTRY_URL` is set and the import is configured; otherwise it hands the plugin an opener that returns `readOnlyRegistry(registryImport.registry)` (campaigns.list and campaigns.get only, no migrate, no close of the import's connection). `campaignsPlugin` throws when given neither a registry nor an opener; the default opener, `defaultRegistryPath` and `KIDS_REGISTRY_PATH` are gone. The runtime starts the import first and installs the plugin only from it. Tests (`tests/campaigns-plugin.test.mjs`): with the variable unset the three routes answer 404 `Not found` exactly as before the slice, `/_health/status` has no `registry` block and no `localnet/.runtime/registry.sqlite` appears; with the variable set the routes serve the rows the import wrote to the one file, the read-only view has no `upsert`, and closing the plugin leaves the import's connection open.

### M2. Signer accepts any fencing token; the "stale runner cannot sign" guarantee is not implemented
- **Where:** `localnet/signer/capabilities.mjs:63` (`if(!Number.isSafeInteger(fencingToken)||fencingToken<1)return fail(...)`), `localnet/signer-service.mjs:42` (token passed through, then only logged at :55). Design text at `capabilities.mjs:4-5` and `localnet/jobs/runner.mjs:2-4` says the token stops a runner whose lease expired.
- **Scenario:** Runner A holds job J (token 5), passes `ctx.fenced` (`registry.jobs.holds`), then stalls. Its lease expires; runner B leases J (token 6) and settles receipt R. Runner A wakes and posts its already-built message with `fencingToken:5`. The signer cannot see the registry and signs. What actually saves the day is the operation-id replay check (`operationId` `settle:<campaign>:<receipt>` bound to one message hash): A's message is either identical (same blockhash, a harmless duplicate the chain de-duplicates) or different (refused 409). The chain's settle and refund are idempotent, so no double payout was found. The token itself is decorative.
- **Impact:** A claimed control does not exist; protection rests entirely on deterministic operation ids and on-chain idempotency. Any future handler with a non-deterministic operation id (a fresh UUID per attempt) would lose the protection silently.
- **Fix:** Enforce monotonic tokens inside the signer's own durable state: keep the highest `(campaign, operationId prefix)` token seen in `signer-state.json` and refuse a lower one (409 "stale fencing token"). Longer term, have the API attest `(jobId, token, owner, expiresAt)` with a key the signer verifies, or let the signer read the registry. Add a test that a lower token after a higher one is refused.
- **Status: fixed (signer-side mark).** The signer's state file gains `fences`, a map of `campaign|operationKey` (the job's operation key sent as `operationKey`; the operation id itself when a request carries none) to the highest fencing token it has signed for. A lower token is refused with 409 `{error:'stale fencing token', category:'stale-fencing-token'}` and logged with its category; equal (a retry of the same lease) or higher (a newer lease) is accepted and raises the mark. The mark rises only for a signed request, so a refusal on budget, replay or policy never advances it. An older state file without `fences` loads with none. The legacy path is untouched. Tests (`localnet/signer/capabilities.test.mjs`): stale refused, equal and higher accepted, a second job of the same campaign has its own mark, a refused request does not raise it, and the mark survives a restart of the service on the same state file. The API attestation of `(jobId, token, owner, expiresAt)` remains the longer-term item.

### M3. Creator media URLs are rendered without validation (only links are https-only)
- **Where:** `interaction-review/src/public/campaign-adapter.mjs:124` (`media.pfp/banner/video/videoCaption/poster` via `str()` only) and `:119` (`parents[].logo`), versus `:125` and `:149` where `links.x/website` and `explorerUrl` go through `safeHttps`. Sinks: `src/public/CoinMedia.jsx:13` (`<img src>`), `:26` (`<video src autoPlay>`), `:27` (inline style `background:'url('+vm.media.poster+')'`), `src/public/CoinIdentity.jsx:46,59`, `src/public/ClaimsSummary.jsx:15`, `src/public/CoinStep.jsx:6,11`. The SPA has no Content-Security-Policy (the only CSP is on the gate's lock page, `deployment/gate.mjs:44`).
- **Scenario:** A creator's profile (once the create route exists, or via an API record) sets `media.pfp` to `http://tracker.example/p.gif?c=<campaign>` or `media.video` to a 2 GB file on an arbitrary host. Every viewer's browser fetches it: IP and referrer leak to a third party, mixed content on https, bandwidth abuse. `poster` is concatenated into CSS; React sets it as one property value so no new declarations can be injected, but a `)` or quote breaks the style. Script execution was not found (React escapes text; `<img>`/`<video>` contexts do not run script; `data:image/svg+xml` in `<img>` is scriptless).
- **Impact:** Privacy leak and abuse of viewers' bandwidth, not script injection. Engineering rules section 6 require validated media URLs.
- **Fix:** Apply one `safeMediaUrl` to every media and logo field: https only, host on an allow-list (the platform content store), optional `data:image/(png|jpeg|webp|svg+xml)` only if fixtures must keep it. Render the poster with `<video poster>` or an `<img>` rather than string-built CSS. Add a CSP (`img-src`, `media-src`) on the served site.
- **Status: fixed.** `src/public/media-hosts.mjs` exports the allow-list (`SITE_HOSTS`: kids.fun, www.kids.fun and the Vercel alias from `deployment/README.md`; `MEDIA_HOSTS` is the same list because the deployed campaign records under `deployment/` reference only `interaction-review/public/assets`, so no ipfs.io or gateway.pinata.cloud is listed) and `safeMediaUrl(value,{kind})`: a same-origin path, https on an allowed host, or for images a `data:` URL of an image type (bounded size); video takes no `data:`; credentials, whitespace, backslashes, protocol-relative and every other scheme or host give null, which every component already renders as the placeholder. The adapter applies it to `pfp`, `banner`, `poster`, `video` and each parent `logo`; `normalizeManifest` applies it to the preset manifest's parent logos before the launch wizard sees them. `CoinMedia.jsx` renders the poster as an `<img>` inside the play button; no `url()` is built from data anywhere in `src/`. CSP: the site has none today and the gate sets one on its own lock page only, so `vite.config.mjs` injects `<meta http-equiv="Content-Security-Policy">` with `img-src` and `media-src` (self, blob:, data: for images, the allow-listed hosts) only when `VITE_KIDS_PUBLIC_LAUNCHES=1`; the flag-off `index.html` is byte-identical to before. `script-src`, `style-src` and `connect-src` are deferred: the inline analytics bootstrap in `index.html`, the wallet standard and the chart library need verifying against them first, and a wrong value there would break the live site rather than a dark page. Tests (`tests/public-adapter.test.mjs`) cover every accepted and refused form, the adapter fields, the manifest logos, the host list and the exact directive string.

## Low

### L1. Public campaign JSON leaks internal plan fields
- **Where:** `interaction-review/server/campaigns-plugin.mjs:14` (`const {sourcePaths,ordinal,...rest}=row` then spreads everything else); `localnet/registry/import-legacy.mjs:44` stores `terms.snapshotDirectory`, `terms.plannedAt`; `:35` stores `terms.programSha256`, `terms.feeNft`; `:52` stores `terms.note`.
- **Scenario:** `GET /api/campaigns/<id>` returns `terms.snapshotDirectory: "deployment/mainnet/snapshots/9Fjw..."` (real value in `deployment/mainnet/campaign-plan.json:33`), the plan time and the program hash. Repository layout disclosure only; no secret.
- **Fix:** Build the public row from an explicit field list; keep `terms` to sealed money terms.
- **Status: fixed.** `publicCampaign` copies `PUBLIC_CAMPAIGN_FIELDS` only and `terms` from `PUBLIC_TERMS_FIELDS` (`deadlineSeconds`, `feeNft`, `note`); `snapshotDirectory`, `plannedAt`, `programSha256`, `sourcePaths`, `ordinal` and any unknown column never reach the JSON. Test: a row carrying all of them is served on the list and item routes with none of them.

### L2. A `node_modules` symlink to the owner's absolute local path is committed on the branch
- **Where:** `git ls-tree feature/public-launches babies-launchpad/interaction-review/node_modules` is mode `120000` pointing at an absolute path under the owner's home directory (the path itself is not repeated here). It passed `.gitignore` because `node_modules/` (trailing slash) matches directories only, and `.dockerignore`'s `**/node_modules/**` excludes contents, not the link.
- **Scenario:** Pushing the branch publishes the owner's home directory path. In the Docker build the link is copied dangling; `npm ci` normally replaces it (unconfirmed on this image). On a Vercel build it is a dangling link until install.
- **Fix:** `git rm --cached babies-launchpad/interaction-review/node_modules` before merge; add a bare `node_modules` line to `.gitignore`.
- **Status: fixed earlier on the branch.** Commit `d6e25fd` removed the link; `git ls-tree` of the branch head shows no `node_modules` entry. The bare `node_modules` ignore line is added with this change where it was missing.

### L3. Malformed coin link blanks the flagged site
- **Where:** `interaction-review/src/public/PublicLaunches.jsx:10` (`decodeURIComponent(parts[1])` in `subFromHash`, used as a `useState` initialiser at :18 and in the hashchange handler at :21).
- **Scenario:** A shared link `https://kids.fun/#coin/%E0` throws `URIError` during render; there is no error boundary, so React unmounts the whole app. Only with `VITE_KIDS_PUBLIC_LAUNCHES=1`.
- **Fix:** Wrap the decode in try/catch and return null (shows "No launch with that address").
- **Status: fixed.** `subFromHash(hash)` and `coinHref` moved to `src/public/routes.mjs`; a bad escape returns null and the page renders "No launch with that address". Test (`tests/public-routes.test.mjs`): round trip, empty and malformed hashes.

### L4. Fee-cycle job runs the keeper before checking which campaign it served
- **Where:** `localnet/jobs/handlers.mjs:116-120`: the `enabledCampaigns` gate checks the job's campaign, then `tick()` runs the legacy keeper (which resolves the process's own active campaign), and the mismatch is detected only from the result.
- **Scenario:** A job for enabled campaign X in a process whose active campaign is Y performs Y's collect, buy-back or burn, then reports `campaign-mismatch`. Money stays inside Y's own fee cycle, so no misdirection, but the per-campaign enablement is not a real gate. Not wired in production yet.
- **Fix:** Resolve the active campaign first and refuse before ticking; or pass the job's identity into the keeper and let it refuse.
- **Status: fixed.** `feeCycle` requires `servedCampaign` (the campaign the legacy keeper would serve, from the same manifest it reads) and resolves it before any tick: another campaign is `failed-permanent campaign-mismatch` with nothing ticked; an unresolved or empty answer is a `retry served-campaign-unresolved`, never a tick. The post-tick check stays. Test (`localnet/jobs/handlers.test.mjs`): the tick counter does not move on a mismatch or an unresolved served campaign.

### L5. Registry accepts never-grantable capability tags at grant time
- **Where:** `localnet/registry/registry.mjs:301` accepts any tag 0..255; `localnet/signer/capabilities.mjs:29` rejects tags 0, 9, 1, 7, 8, 10 only when loading; `signer-policy.mjs:77` would also refuse them at signing.
- **Scenario:** An operator tool grants tag 0 (init campaign); the row is stored and silently skipped with reason "never be granted". Defence in depth only.
- **Fix:** Import `NEVER_GRANTABLE_TAGS` into the registry and refuse at `grant()`.
- **Status: fixed.** `NEVER_GRANTABLE_TAGS` now lives in `signer-policy.mjs` (re-exported by `signer/capabilities.mjs`) and `registry.capabilities.grant` refuses any of them with the signer's own wording; nothing is stored. Test: every never-grantable tag is refused at grant time and the grant count is unchanged.

## Info
- **I1.** `GET /healthz` on the signer advertises `capabilities:true` (`signer-service.mjs:25`). Harmless; keep it if the API's status page needs it. **Status: kept.**
- **I2.** `node:sqlite` is synchronous; the import (`startup.mjs`) and the plugin (`campaigns-plugin.mjs`) each open a connection in the API process. `BEGIN IMMEDIATE` with `busy_timeout=5000` can block the event loop up to 5 s when the two write at once (first request during an import). Small today; worth one shared connection (see M1). **Status: resolved by the M1 fix**, the routes read through the import's connection.
- **I3.** `runner.mjs:24` treats any message containing a three-digit `5xx` number as transient (`/\b5\d\d\b/`); "500 lamports short" would be retried. Tighten to `HTTP 5xx` or a status code field. **Status: open**, separate change.

## Verified sound
- **SQL.** Every statement in `registry.mjs` is parameterised; column names come from constant arrays; migrations are repo files split on line-ending semicolons; `toPostgresPlaceholders` is safe because no SQL literal contains `?`.
- **Legacy import.** No user input reaches a path. Runtime archive folder names must match the base58 regex and the manifest's own campaign; plan archive file names must equal `campaign-plan-<campaign>.json`; only addresses are read from `MAINNET-IDENTITIES.json`; `sourcePaths` are stripped from every public response (test asserts it).
- **Campaign routes.** Id validated by regex (address or `genesis:program:campaign`, length-bounded), 409 on an ambiguous address, query keys allow-listed, cursor validated (base64url, safe integer), page fixed at 50, non-GET 405, item routes refuse any query, `cache-control: no-store` and `nosniff`; `readView` is not wired so no chain read amplification; middleware rejections become 500 in `createApiServer`, never a crash. Gate and gateway allow exactly these GETs (tests cover).
- **Signer capability path.** Refused with 403 when the service has no `capabilities` option, and `startSignerService` never sets it, so the path is unreachable in production; the legacy path is byte-for-byte unchanged. A grant can only lower `DEFAULT_LIMITS`; `provisioning` is always false; `recipients:null` means operator plus the campaign's own authorities only (`signer-policy.mjs:47`); every `kids:` op must be in the grant; a request without a launch-program op is refused; `operationId` is bound to one message hash (409 on reuse). Logs carry the campaign and token, never key material; the request campaign is length-bounded.
- **Job runner.** Lease is a compare-and-set on `(job_id, fencing_token, state)`; the token grows on every lease; `complete`, `fail`, `requeue` and `renew` need the current token; a stale runner is logged and performs no registry write (test at `runner.test.mjs:73`); `unknown` outcomes are reconciled from the chain before any rerun and never turned into failure; owner ids are validated.
- **Mint leases.** The public view exposes `leaseId, mint, state, campaign, network` only; no private key is ever handled; a signed-pending lease is never returned to stock; release needs inventory proof plus chain absence; a timeout releases nothing.
- **Budgets.** BigInt only, non-negative, one row per (campaign, payer), a shortfall is reported and never covered by another campaign.
- **Dark flags (build evidence).** Three production builds from the branch tree: flag off gives no public-page code and no fixture strings in `dist`; flag on with fixtures off gives the pages but no fixture chunk; fixtures appear only with `VITE_KIDS_PUBLIC_LAUNCHES_FIXTURES=1` (`public-launches-*.js`). The `go()` hash change in `App.jsx` is behaviour-preserving with the flag off. The startup import runs only with `KIDS_REGISTRY_URL`.
- **Pages.** All creator text is rendered through JSX (escaped); no `dangerouslySetInnerHTML`, `innerHTML` or `eval` in the new code; X and website links are https-only, `rel="noreferrer noopener"`; the draft validates X links to a handle on x.com/twitter.com and websites to https without credentials; nothing in the browser code holds a secret.
- **Packaging.** Railway image is Node 24 (`node:sqlite` already used in production); `COPY babies-launchpad ./` includes the new `localnet/registry`, `jobs`, `signer`, `mints` folders; `.runtime` is a link to `/data`, so the default SQLite lands on the volume.
